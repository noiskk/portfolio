# 강점·협업·성장 경험

## 강점
- 정상 흐름보다 예외·복구·추적 가능성을 먼저 보는 백엔드·인프라 개발자
- 이중화는 구성했다고 끝이 아니라 실제 장애 전환을 확인해야 끝난다고 보고, SOFIT에서 MySQL Primary를 강제로 중단해 Secondary 자동 승격과 서비스 연속성을 직접 확인
- 규정 항목을 채우는 데서 멈추지 않고 그 규정이 막으려는 위험을 실제로 차단하는지 확인 — 감사 로그에서 애플리케이션만 막으면 DB 직접 접근 경로가 남는다고 보고 DB 트리거로 수정·삭제까지 차단
- 이 사이트의 챗봇에서도 같은 기준 적용 — 관련 문서가 없으면 지어내지 않고 안내하고, 답변마다 근거 문서를 표시하고, 챗봇 장애가 사이트 전체로 번지지 않게 격리

## 단점과 개선
- 단점: SOFIT에서 인프라를 맡은 책임감 때문에 혼자 해결하려다 진행 상황과 막힌 지점을 늦게 공유했고, 그 때문에 팀이 일정 위험을 판단하기 어려웠음
- 개선: 이후 진행 상황과 작업량을 팀에 공유하고, 우선순위를 함께 정하고, 배포 검증과 테스트를 분담하는 방식으로 바꿈

## 협업 경험
- SOFIT: 5명 팀(PM, TL·AI, Backend, Infra, Frontend)에서 Infra Leader로 AWS·온프레미스 하이브리드 인프라를 맡고 백엔드 일부(마이비즈 대시보드·약관 동의·심사결과 API)에 참여. AI 모델 개발은 다른 팀원 담당이며, 최종프로젝트 최우수상은 팀 전체의 성과
- BookCard(졸업작품 팀 프로젝트): 매주 회의에서 아이디어와 구현 가능성을 정리하고 핵심 기술을 실험해 팀에 공유. 통합 단계에서 API·데이터 형식 불일치를 목록화해 우선순위를 나눠 함께 수정. 교내 졸업작품 최우수상
- 의사결정 근거를 남기는 습관: SOFIT에서 의사결정 로그(ADR) 58건, 트러블슈팅 일지 30여 일치를 기록

## 다른 의견을 조율한 경험
- 상황: BookCard 팀 프로젝트에서 생성형 AI 활용 범위를 두고 의견이 달랐음. 팀원은 아이디어·문서·코드를 빠르게 만드는 속도를 중시했고, 본인은 결과를 이해하고 검토한 뒤 반영해야 한다고 봄
- 과정: 통합 과정에서 API·데이터 형식 불일치와 문서·구현 차이가 나타나자, 속도의 장점은 인정하면서 문제가 난 코드와 문서를 함께 확인하며 공통 기준이 필요한 이유를 설명
- 결과: 초안과 구현 참고에는 AI를 자유롭게 쓰되 최종 결과물은 담당자가 직접 검토하고 설명할 수 있어야 한다는 기준에 합의. 기능 간 인터페이스를 먼저 정하고 통합 전에 서로의 코드를 확인하는 방식으로 진행

## 어려움을 극복한 경험
- 제약 안에서의 하이브리드 연결(SOFIT): 온프레미스에 공인 IP가 없어 AWS 표준 Site-to-Site VPN을 쓸 수 없었음. 온프레미스가 먼저 연결을 시작하는 WireGuard 터널로 대안을 설계해, 네트워크·비용 제약 안에서 실제로 동작하는 방법을 선택
- 제한된 자원에서의 DB 이중화(SOFIT): 단일 MySQL이 전체 서비스의 단일 장애점이라고 판단하고 InnoDB Cluster 3노드를 구성. vCPU 쿼터가 부족하자 기존 인스턴스를 다운사이징해 신규 노드 자원을 확보하고 자동 failover를 검증

## 실패 후 개선한 경험
- 상황: BookCard로 졸업작품 최우수상을 받은 뒤에도 설계와 동작 원리를 충분히 설명하지 못한다는 아쉬움이 남음
- 행동: 졸업 후 혼자 Spring Boot로 재구현. 요구사항 명세서와 10단계 개발 가이드를 먼저 작성하고 Spring Security·JWT 인증 구조를 직접 설계
- 개선 1 (트랜잭션 범위): 생성 전 과정(AI 호출 약 21초 포함)을 하나의 트랜잭션으로 묶어 두었더니 DB 커넥션을 그 시간 내내 점유해 커넥션 풀이 고갈될 수 있었음. AI 호출은 트랜잭션 밖에서 실행하고 DB 저장 구간만 짧은 트랜잭션(TransactionTemplate)으로 묶도록 수정해 커넥션 점유를 약 21초에서 저장 시간(수십 ms) 수준으로 줄임
- 개선 2 (동시성): 좋아요 수를 조회 후 덮어쓰는 방식은 동시 요청에서 갱신이 유실될 수 있어, 원자적 UPDATE 쿼리로 바꿈
- 개선 3 (정합성): 북카드 삭제는 DB를 먼저 지우고 파일을 나중에 지우도록 순서를 바꿔, DB 삭제가 롤백되면 파일이 보존되게 함. 회원가입은 중복 체크와 저장을 한 트랜잭션으로 묶음
- 계층별 테스트를 새 구조에 맞게 다시 작성하며 기존 설계의 결함을 보완
- 배운 점: 결과가 좋아도 구조와 실패 조건을 설명할 수 없다면 끝난 프로젝트가 아니다

## 새로운 기술을 학습해 가치로 연결한 경험
- SOFIT: 소상공인이 대출에 어려움을 겪는 현실을 알고 있었고, 프로젝트 주제를 찾는 과정에서 금융위원회의 SCB(비금융 데이터 기반 신용평가)를 발견해 학습. LightGBM의 등급 산출과 SHAP의 영향 요인 설명 방식을 이해하고 팀원들과 대출 심사 플랫폼으로 기획
- 본인은 인프라와 백엔드를 맡아 비금융 데이터와 산출 등급·영향 요인이 심사 결과로 이어지는 데이터 구조와 API를 구현해, AI 평가가 시연에 머물지 않고 대출 신청·심사·약정·실행 흐름에서 쓰이게 함
- 이 포트폴리오 챗봇: 프로젝트 이력이 자주 바뀌므로 모델을 재학습하지 않고 문서만 고치면 되는 RAG를 선택하고, 문서 분할 → 임베딩 → 벡터 저장 → 검색 → 답변 생성을 단계별로 나눠 학습하며 구현

## 성실성과 책임감 (영화관 근무)
- 약 2년 4개월 동안 영화관에서 고객 응대·결제·현금 정산·이벤트 운영을 담당
- 같은 질문과 실수가 반복되는 원인이 구두 인수인계에 있다고 보고 돌발 상황별 응대 시나리오와 실무 체크리스트를 문서로 작성하고 신입 교육을 전담
- 성수기와 인원 공백에 대비해 매일 20분 일찍 출근해 업무를 점검
- 설 명절 굿즈 이벤트에서 동료와 고객층별 접근을 나눔 — 아이에게는 경품의 매력, 부모에게는 합리적 소비를 설명. 전국 지점 매출 2위
